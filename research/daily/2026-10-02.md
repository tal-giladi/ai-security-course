### C-20261002-01 · ZoneClaw — hierarchical trust zones stop persistent-memory attacks on computer-use agents, with code and a strong measured cost

- **Class:** A
- **Date discovered:** 2026-10-02
- **Date published:** 2026-09-30
- **Source:** https://arxiv.org/abs/2610.00450
- **Organization/researchers:** Haokai Ma, Chieh Lin, Yupeng Qiu, Ee-Chien Chang. Affiliation not stated on the abstract page.
- **Category:** agent-security
- **What changed:** Names and defends against a "persistent memory attack" on OpenClaw-style computer-use agents (CUAs): attacker-controlled benign-looking content induces the agent to write attacker-favored claims into its auto-reloaded workspace memory during one task, and those claims silently govern unrelated later tasks the attacker never touched — extending "malicious context -> malicious response" into "malicious context -> memory injection -> malicious execution."
- **Technical summary:** Diagnoses the root cause as flat workspace memory where persistence and action-guiding authority are the same thing. ZoneClaw separates them: external claims persist in a low-trust zone and only gain authority over actions by crossing an explicit boundary, cross-checked against zones the attacker cannot write, enforced by role-specific processes of asymmetric privilege (no single process both ingests external content and acts outward). Across 4 attack scenarios x 2 injection settings x 4 model backbones, ASR falls from 372/480 (77.5%) to 6/480 (1.25%) while benign utility is retained in 458/480 trials (95.4%); the paper states it remains effective against some defense-aware attackers. Code released: https://github.com/euph00/ZoneClaw-code.
- **Why it might matter:** A reproducible, code-released defense with both a large attack-success reduction and a stated, high utility-retention number — exactly the course's `.callout.guarantee` shape — against a persistent-memory attack surface the course already names generally (module-16/18) but has not seen instantiated against today's long-running "computer-use agent with auto-reloaded memory files" pattern (OpenClaw-style). The attacker-adapts angle is already in the paper (partial residual success against defense-aware attackers), which is useful for teaching the "what this does NOT guarantee" half.
- **Evidence of adoption:** None yet (days-old research prototype); code is released but not reported adopted elsewhere.
- **Major organizations using it:** none stated.
- **Open-source implementation:** https://github.com/euph00/ZoneClaw-code
- **Paper:** https://arxiv.org/abs/2610.00450
- **Code:** https://github.com/euph00/ZoneClaw-code
- **Relationship to existing course material:** Extends `module-16`/`module-18` (agent memory as a durable, cross-session injection channel; `labs/module-16/README.md` already covers agent memory poisoning & persistence generally) with a concrete, computer-use-agent-specific architecture (hierarchical trust zones / authority boundary) and measured numbers. `lookup "memory zoning"` / `"persistent memory attack"` → no prior match; this is new instantiation evidence, not a duplicate.
- **Potential course lesson:** module-16/18 lab extension: add a "trust-zoned memory" variant to the existing lab-16 memory-poisoning lab, replay the same injected-claim scenario against flat vs. zoned memory, and measure the ASR/utility trade-off exactly as the paper does.
- **Confidence:** high (one research group but a large, structured evaluation — 4 scenarios x 2 settings x 4 backbones — with both attack and defense-aware-attacker numbers, and released code to verify).
- **Recommendation:** review for ADD as a module-16/18 lab extension; unusually complete single-paper evidence (attack, defense, cost, code).

### C-20261002-02 · LLMLeak ("The Innocent Courier") — covert data exfiltration through an LLM's legitimate web-fetch tool, no code execution needed

- **Class:** B
- **Date discovered:** 2026-10-02
- **Date published:** 2026-10-01
- **Source:** https://arxiv.org/abs/2610.01768
- **Organization/researchers:** Alessandro Pegoraro, Daryan Merx, Phillip Rieger, Ahmad-Reza Sadeghi. Affiliation not stated on the abstract page.
- **Category:** agent-security
- **What changed:** A covert-channel attack distinct from code-based exfiltration (which is easy to detect/restrict via sandboxed network libraries): local malicious software that cannot itself reach the internet embeds a secret into a URL framed as needed for a benign task (e.g. "migrating a software library"), and the LLM's own legitimate web-fetch tool call — not attacker code — carries the secret out to an attacker-controlled DNS/web server.
- **Technical summary:** Evaluated across eleven open-parameter models with a reported 79.7% attack success rate, plus a case study against real-world chatbots "demonstrating the relevance" of the technique. No defense or detection mechanism is proposed; this is attack-capability evidence only.
- **Why it might matter:** A structurally new exfiltration mechanism (abusing a legitimate, commonly-granted tool capability rather than code execution or a direct network call) that is adjacent to, but mechanistically distinct from, the course's already-deferred `dns-covert-channel-agent-egress` topic (which covers DNS-as-data-channel and URL/TLD allowlist bypass): there the data channel itself is DNS; here the covert channel is the LLM's own web-fetch tool, with DNS/web-server collection as the receiving end. Quantified across 11 models plus a real-chatbot case study, but single paper, no defense proposed.
- **Evidence of adoption:** None (research result, days old; case study against real chatbots is a demonstration, not a reported real-world incident).
- **Major organizations using it:** none stated.
- **Open-source implementation:** not stated on the abstract page.
- **Paper:** https://arxiv.org/abs/2610.01768
- **Code:** none confirmed
- **Relationship to existing course material:** Directly relevant to the registry's WAIT topic `research/deferred/dns-covert-channel-agent-egress.md` (next review 2026-10-04) — same egress-control-bypass family, different mechanism (tool-call carrier vs. DNS-as-channel directly); flag for that topic's imminent review to consider together rather than as a separate decision. `lookup "web fetching exfiltration"` → no match; `lookup "DNS covert channel"` → matches only the existing deferred topic.
- **Potential course lesson:** if the DNS-covert-channel topic is ADDed, extend its lab with a second carrier variant: a benign-looking "fetch this doc" tool call that leaks a canary secret via the fetched URL, to show that egress-channel attacks generalize beyond DNS to any tool the agent is allowed to call outward.
- **Confidence:** medium (single paper, but quantified across 11 models plus a real-system case study; no independent replication, no proposed defense).
- **Recommendation:** monitor alongside the dns-covert-channel-agent-egress WAIT topic; recommend the 2026-10-04 review consider both together as one "egress covert-channel" lesson rather than two.

### C-20261002-03 · OverAct — benchmarking and reducing "proactive over-authorization" in tool-calling LLM agents

- **Class:** B
- **Date discovered:** 2026-10-02
- **Date published:** 2026-10-01
- **Source:** https://arxiv.org/abs/2610.01508
- **Organization/researchers:** Taolin Zhang, Jiuheng Wan, Hanyu Wang, Tingyuan Hu, Chengyu Wang. Affiliation not stated on the abstract page.
- **Category:** agent-security
- **What changed:** Names and measures a failure mode distinct from classic excessive-agency/confused-deputy framing: a tool-calling agent, with no attacker involved at all, retrieving more private information than a user's own request required ("proactive over-authorization"), and proposes a zero-shot inference-time filter.
- **Technical summary:** OverAct is a controlled benchmark across 8 privacy-sensitive domains with deterministic, judge-free scoring. Across 7 models from 4 model families, all models significantly exceed authorized scope; over-authorization severity is best predicted by request specificity, grows only sublinearly with tool-pool size, and is largely insensitive to decoding temperature (consistent with a structural "cost-asymmetry" decision tendency rather than sampling noise). SelfAudit, a proposed zero-shot method that generates request-grounded justifications and filters unjustified tool calls before execution, reduces privacy-oriented excess by 43% without oracle knowledge of what was actually needed; an ablation shows explicit filtering (not the justification step) drives most of the reduction.
- **Why it might matter:** A new, benign-trigger failure mode (no adversarial input needed) for the course's excessive-agency material, with a real benchmark across 7 models/4 families and a measured, no-oracle mitigation with a stated effect size (43% reduction) — a clean `.callout.guarantee`-shaped result, though the paper's abstract does not give an explicit benign-utility cost number for SelfAudit itself, only the ASR-style reduction.
- **Evidence of adoption:** None yet (single paper, days old).
- **Major organizations using it:** none stated.
- **Open-source implementation:** not stated on the abstract page.
- **Paper:** https://arxiv.org/abs/2610.01508
- **Code:** none confirmed
- **Relationship to existing course material:** New, non-adversarial angle on `module-16`/`module-21` (excessive agency / least privilege) — distinguishes "agent asked to do X, does more than X with no attacker present" from the course's usual attacker-induced scope violations (e.g. the already-staged `C-20260929-01` AISI/ScopeBench result, which is attacker/goal-pressure-driven). `lookup "over-authorization"` / `"proactive over-authorization"` → no matches.
- **Potential course lesson:** module-16/21 exercise: build a small multi-domain tool-calling task set where the minimal-vs-available tool scope differs, measure baseline over-retrieval across locally available models, then implement SelfAudit's justify-and-filter pattern and reproduce the reduction.
- **Confidence:** medium (single paper, but a real 7-model/4-family benchmark, a clearly stated structural explanation, and a measured, oracle-free mitigation).
- **Recommendation:** monitor; revisit for ADD if independently replicated, or pair with `C-20260929-01` at the weekly review as two distinct causes (goal-pressure-driven vs. structurally-driven) of the same excessive-agency symptom.
